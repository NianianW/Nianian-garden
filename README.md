# 小猫植物园 · 本地优先 PWA

这是念念的两页植物园：**今日巡园**只管理浇水、喷雾、施肥和除虫；**植物手记**只记录植物的成长观察、猜想、待观察问题、照片与专属养护档案。养护操作不会出现在成长日记里。资料匣是两页共同使用的聊天导入与备份工具，不是第三个主页面。

## 现在在 Mac 上使用

直接双击 `index.html`，或把它拖进 Chrome，就可以开始使用。页面地址会以 `file://` 开头，这是本地版本的正常状态。无需安装依赖、注册账号或运行命令。请把整个 `xiaomao-plants` 文件夹放在固定位置；以后若要移动它，先在「资料匣 → 备份与恢复」下载完整备份。

1. 在「今日巡园」新增一盆植物；点浇水、喷雾、施肥或除虫可以修改日期后记录。每盆植物可选择检查周期及提醒依据。
2. 点击「查看养护日历」，用月历或列表回看记录；可按植物及操作筛选，也可补记、修改和删除。
3. 在植物档案里开启「土壤湿度记录」后，今日巡园卡片会出现“记录”和“趋势”。读数为 1–10，可标为日常检查、浇水前或浇水后；趋势可切换最近 14 天、30 天和全部，并标出浇水日期。
4. 在「植物手记」写观察，可添加照片与光照、温度、空气湿度。观察事实、猜想和待观察问题会按时间排列。土壤湿度读数不会生成成长日记。
5. 每盆植物的「专属养护档案」可以持续编辑；成长相册可选择两个日期进行对比。
6. 在「资料匣 → 导入聊天整理稿」复制整理请求给 ChatGPT，把返回的整段内容原样粘贴。网页会自动识别普通 JSON 或代码框，并立即进入预览。**逐条核对证据、类别、日期和重复提示，然后勾选保存。**养护知识会先显示原有内容和导入结果，可选择新增、合并、修订或忽略，并区分已验证经验与待验证推测。也可以只导入植物基本资料或养护知识。
7. 整理日期可以在导入前修改；成功后，资料匣会显示最近一次整理日期。
8. 在「资料匣 → 备份与恢复」定期下载完整 JSON。备份包含缩小后的照片、湿度读数、专属养护档案修订记录和最近整理日期。恢复支持合并或替换，替换前先导出当前数据。

聊天导入格式见 [`chat-import-schema.json`](./chat-import-schema.json)。[`example-import.json`](./example-import.json) 只是审核练习，全部标为演示并默认不勾选。网页不会把聊天发到服务端，也不能直接读取 ChatGPT 对话。可行流程是：ChatGPT 整理 → 复制整段结果 → 粘贴 → 预览确认。

## 旧数据兼容

这次更新把 IndexedDB 从 v1 平滑升级到 v2，并新增 `meta` 存储区，不删除旧字段。已有植物与记录会直接继续使用：旧植物未设置提醒依据时默认按浇水计算；旧养护记录自动进入养护日历并从成长日记中隐藏；旧版「专属养护知识」仍显示在档案的旧记录区域，首次编辑档案时会带入“有效的养护经验”供修订。备份格式继续使用 `xiaomao-backup` v1。

## 建议测试

1. 新增一盆测试植物，分别记录一次浇水与一次观察，确认浇水只出现在养护日历、观察只出现在成长日记。
2. 新增除虫并填写药剂、部位和备注，在月历日期详情及列表中检查内容，再测试修改和删除。
3. 修改植物的检查周期与提醒依据，确认提示文案为“可以检查一下了”。
4. 在成长日记添加带环境数据和照片的观察；两张照片后测试成长对比选择器。
5. 开启一盆植物的土壤湿度记录，新增、修改和删除读数；检查 14 天、30 天和全部趋势，并确认浇水日期有标记。
6. 导入一条专属养护知识，分别检查新增、合并、修订和忽略；确认原内容不被静默覆盖，修订历史保留来源日期与证据状态。
7. 将同一份整理稿导入两次，确认浇水、湿度和养护知识都出现重复提示，且默认不勾选。
8. 再试一份 `entries: []` 的整理稿，确认可以只导入植物资料；修改整理日期后确认资料匣显示该日期。
9. 导出完整备份，再用“合并”方式恢复，确认湿度、养护档案历史和最近整理日期仍在，重复记录被跳过。

想快速查看相册效果，可在没有照片的成长相册中点击「看看五个月相册示例」，或到「资料匣 → 导入聊天整理稿 → 装入五个月相册」。它会为「演示｜小白鹰」加入 2026 年 6 月至 10 月的五张合成演示图。图片和记录均明确标注为演示，不代表真实观察或真实生长速度。

## iPhone 与 GitHub Pages

将这个文件夹的**全部文件**提交到 GitHub 仓库，设置 Pages 从根目录发布。资源路径均为相对路径，可放在项目仓库子路径。GitHub Pages 的 HTTPS 可让浏览器注册离线缓存；iPhone 用 Safari 打开发布网址后，可通过分享菜单加入主屏幕。请在真实 iPhone 上再检查一次安装与离线表现。

**同一网址在 Mac、iPhone 和不同浏览器中的 IndexedDB 互不相通。** iPhone 无法直接读取 Mac 浏览器的数据；需要先在 Mac 导出，再把 JSON 文件传到 iPhone，在 iPhone 上恢复。无云数据库，也无自动同步。浏览器清理网站数据或设备故障会使本地记录丢失，所以要保留备份。照片会增大备份文件。检查提示只在打开网页时显示；无其他服务就无法可靠地在后台准时推送通知。

## 修改代码后重新打包

页面实际加载的是 `app.bundle.js`（单个普通脚本，所以双击 `index.html` 也能用）。修改 `core.js`、`db.js`、`app.js` 或 `example-import.json` 后，运行：

```
node work/build-file-bundle.mjs
```

再把 `sw.js` 里的缓存名（`xiaomao-static-vN`）加一，确保已安装到主屏幕的版本会拿到新文件。

## 数据与版本

IndexedDB 存 `plants`、`entries` 与 `meta`。完整备份格式 `xiaomao-backup` v1；聊天整理稿格式 `xiaomao-chat-import` v1。数据导入前执行格式检查。相同植物、日期、护理动作被视为可能重复；湿度按植物、时间、读数和场景比对；养护知识按栏目、来源日期和原文比对。合并备份时相同 ID 或内容指纹会跳过，替换则用备份覆盖全部本机记录。打开时会向浏览器申请长期保存（`navigator.storage.persist()`），结果显示在资料匣；浏览器不同意时仍可能清理数据。有记录但超过 14 天未下载备份（或从未备份）时，今日巡园顶部会出现「去备份」提示。当前为单人小型 MVP；请不要将含有私人聊天或照片的备份提交到 GitHub。
